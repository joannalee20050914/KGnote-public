# KGnote 整合裁決與衝突紀錄

狀態：本次來源比對的候選整合基線。使用者明示意圖照原話保留；本檔的工程形式與調和方案是建議，不冒充使用者已逐條批准。未連到最新 repository，不能證明目前缺少或已完成任何功能。

## 1. 基本裁決

原始發想與審查在目的上大致一致：降低陌生資訊的理解成本、維持結構與精確上下文、容許模糊與錯誤、以低負擔重曝及逐步輸出保留重要概念。不能用單純聯集融合全部歷史文字，因為原始對話包含被後文修正的 AI 提案；審查也曾錯把「生成加工」落成「先自行寫筆記」。

對產品意圖，依據層次為：最近明確的使用者澄清 → 較早的使用者原話 → 有批准來源的產品決策 → AI 建議／研究導出的設計假說 → 現有實作。這不是系統指令優先序；不覆蓋安全、隱私或執行環境規範。較新文字沒有提到舊需求，不等於撤回舊需求。對技術與研究事實，則另外查證，不能以使用者偏好或AI語氣取代證據。

## 3. 原始發想中最容易被近期工程淡化的六件事

1. **Soak不是Quiz：**原§26明確允許先再見到相似形象、熟悉後才反向輸出。只有Practice+due queue不等於完成。
2. **Resume不是Recent：**原§24–25要知道上次的精確問題、回答、混淆與未做之事；最近文件卡、最近outcome不足以代替。
3. **主題層級不是分桶：**原§18要求像目錄，§19從上到下有分類架構；新回饋再澄清同層關係。
4. **最小必要解說不是關鍵字字典：**原§01/05/07/15已有「目前懂到這裡就夠」；PID例子是具體化，不是全新需求。
5. **零譴責／無債務是可驗收UX：**不是在文字中說「錯誤是observation」，畫面卻有罰分、強制補卡或答錯必寫反省。
6. **系統替你保留脈絡：**原§24–27明確不希望每天維護Learning State；自動化不能變成逐條審核所有筆記才能繼續。

## 4. 審查真正補強，而不是改寫初衷的部分

- 來源忠實、事實正確與標準答案可用性三者分離；錯誤原文留存，題目可被停用。
- 教學容器、學習路徑、領域關係、個人行為分離；canonical graph不替代所有結構。
- Attempt的身份、提示與曝光狀態、回饋revision、重送／衝突、歷史與due資格分離。
- 語意一致不要求同一句／全集；不同表示法有任務範圍，不讓UI projector自行提高confidence。
- 工程測試、人工使用、延遲記憶、新情境應用各有證據；N=1不做普遍宣稱。
- 可回退、資料保存、安全外送、局部故障降級；這些是學習工具可靠使用的基礎。

## 5. 不應從原始對話直接採納的內容

舊AI的能力／智力／記憶診斷、誇張效果數字、免費API與平台現況、未展開的外部引文、特定PID／runtime path／service label、固定八週課綱、1–2概念／3個詞熔斷／60%等數字，都不能直接提升成永久contract。保留它們的角色與時間，而不是刪掉歷史或照抄成真理。

原§20引用的OS filled-exercise與OS-keywords原始附件、本對話引用的原stderr證據與SynthKG報告並未隨本次完整提供；本次不宣稱重新核對其內容。這不妨礙保留使用者對學習經驗的需求。

## 6. 執行期的衝突規則

新的feature proposal未被提到，不算舊意圖撤回。更改must／禁止行為、刪除情境、合併掉一個能力、永久延期或將待驗證標為已批准，需要獨立記錄：原ID、before/after、理由、來源、影響的scenario与測試、批准者/證據、回退方式。普通命名、CSS與內部可逆重構可自主進行，不需每件事來回確認。

自動檢查不能確認使用者真的批准，也不能證明文字語意沒有被稀釋。獨立審查要直接對來源→要求→畫面／行為，不只讀Codex完成報告。
